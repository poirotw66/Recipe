# GSC「已檢索－目前尚未建立索引」分析（2026-08-21）

## 資料範圍

- 匯出來源：Search Console「所有已知的頁面」。
- 問題類型：`已檢索 - 目前尚未建立索引`。
- 趨勢區間：2026-06-01～2026-08-21。
- URL 表格：GSC 僅匯出 1,000 筆範例；介面顯示 1,015 筆，因此不可視為完整 URL 清單。
- 圖表在 2026-08-21 顯示 1,045 筆，與介面後續顯示的 1,015 筆相差 30；應視為 Search Console 重算或匯出快照差異，不可相加。
- 表格中的最後檢索日期最晚為 2026-08-22，全部早於 2026-08-27 的索引修復 commit `6143f79`，因此本報告不能用來評估該修復的效果。

原始 CSV 只作本地分析，不納入版本控制，以免把站務資料永久提交到 repo。

## 主要發現

### 網域污染

1,000 筆範例中：

- `recipe.bloss0m.com`：975 筆。
- `www.bloss0m.com`：25 筆。

`www.bloss0m.com` 包含 blog、feed、JSON index 與 `Clubhouse-Games/*.md`，不屬於 Recipe-master。後續應在 GSC 以 host 過濾，或另建 `https://recipe.bloss0m.com/` URL-prefix property，避免把不同站的問題混算。

### 食譜頁與多語膨脹

剔除 4 個 `/recipes` 列表 URL 後，樣本含 813 個食譜內容 URL，對應 244 個 slug：

| 同一 slug 落入未索引的語系數 | Slug 數 | URL 數 |
| --- | ---: | ---: |
| 4 語 | 133 | 532 |
| 3 語 | 72 | 216 |
| 2 語 | 26 | 52 |
| 1 語 | 13 | 13 |

因此 800/813（98.4%）食譜 URL 屬於「同一 slug 至少兩個語系一起未索引」的群組。以目前 289 slug × 4 語、共 1,156 個食譜頁計算，GSC 的 1,000 筆有限樣本已涵蓋：

- 813/1,156（70.3%）食譜內容 URL。
- 244/289（84.4%）食譜 slug 至少一個語系。

這個分布高度支持「批次多語內容缺少足夠差異與索引價值」是核心問題之一；但此報表本身不能證明人工處分，也不能單獨決定某 URL 應 410、301 或保留。

食譜內容 URL 的語系分布：

- ja：223。
- en：209。
- zh：191。
- ko：190。

非中文共 622/813（76.5%），多語頁是主要治理範圍，但中文也有 191 頁落入同一問題，不能只靠關閉日韓文解決。

### 內容批次

- `sf-*`：240 URL／70 slug；全部 70 slug 至少有一語未索引。
- `dh-*`：50 URL／14 slug。
- 餐廳還原合計：290/813 URL（35.7%）、84/244 slug（34.4%）。
- 非餐廳內容：523 URL／160 slug；代表問題並非只存在於餐廳還原批次。

既有人工審查的 25 個 Critical slug 中，這份有限樣本命中 20 個／65 URL。其餘 5 個沒出現在範例清單，不代表已被索引。既有四語 `noindex, follow` 決策仍以料理錯配、時間與食安稽核為依據，不以本報表反向推論。

其他密集模板群包含 air-fryer、solo、bento、high-protein、electricpot、budget、weight-loss、leftover 與 clearout；應等 Performance 匯出後，依實際查詢與曝光排序，不應僅憑 slug 批次刪除。

### 非食譜頁與技術異常

`recipe.bloss0m.com` 樣本內另有 158 個非食譜 URL，主要為：

- ingredients：96。
- scenarios：26。
- tools：8。
- 其餘：聯絡、條款、隱私、Hub、首頁、404 等。

需要後續檢查 122 個 ingredients／scenarios taxonomy 頁是否內容過薄、互相重疊或缺少內鏈價值。

技術樣本包含：

- 6 個冰箱工具 query URL，證明先前 query URL 已被 Google 發現並抓取。`6143f79` 已讓 crawler 可讀取 `noindex, follow`，並 canonical 到乾淨工具 URL。
- `/404` 與 `/ko/404/`；這些頁不應索引，出現在此分類本身不構成問題，但須維持真正 HTTP 404 與 noindex。
- `/recipes` 與 `/recipes/`、以及部分靜態頁的 slash／no-slash 變體。應統一由 redirect、canonical、sitemap 與內鏈使用單一格式。

## 決策與下一份必要資料

### 已有足夠證據執行

1. 部署 `6143f79`，提交新的 `sitemap-index.xml`。
2. GSC 報表按 `recipe.bloss0m.com` host 分流。
3. 維持 25 個人工稽核 Critical slug 的四語 `noindex, follow`。
4. 維持 sitemap 分批：zh、en、ja/ko pilot 與 core 分開觀察。
5. 抽查並統一 slash redirect、canonical、sitemap 與內鏈格式。
6. 針對 ingredients／scenarios 建立 taxonomy 品質審查批次。

2026-08-28 先完成可逆的 sitemap 收斂：ja／ko 食材與情境頁維持
indexable、self-canonical 與 hreflang，但不再作為整批 taxonomy 主動提交；
zh-TW 與 en taxonomy 保留在 sitemap。內容是否 noindex、合併或刪除仍等待
Performance 資料與逐頁審查。

### 目前證據不足，不執行

- 不因為 URL 位於「已檢索－尚未索引」就全部加 noindex。
- 不把全部日文／韓文 canonical 回中文。
- 不把 1,015 頁大量 301 到 Hub。
- 不在缺少點擊、曝光、查詢與外鏈資料時決定 410。
- 不對整個分類啟動「驗證修正」；目前修復只涵蓋第一批，且報表尚未重抓新版本。

下一步需要匯出：

1. 搜尋成效 → 網頁，過去 16 個月（點擊、曝光、CTR、平均排名）。
2. 「已找到－目前尚未建立索引」URL 表格。
3. 「替代頁面（有適當的標準標記）」URL 表格。
4. 人工處置與安全性問題狀態。

Performance 資料到位後，才能以 slug＋locale 為單位產生 `core / rewrite / noindex / merge / 410` 決策表，並挑出 20～40 個核心頁。
